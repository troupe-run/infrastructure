## Context

`scripts/quality_gates.py` is delivered to troupe and website (`tofu/guard_delivery.tf`, `guard_files`), and each
repository's thresholds live in its own `quality-gates.toml` (quality-gates design D1, D2). Each receiving repository
also holds `.github/guard-delivery.json`, generated by `guard_delivery.tf` from what it receives, which the guard
already reads (`guard.delivered_paths`) to refuse edits to delivered files.

Today troupe leaves delivered files out by hand twice: `[complexity] exclude` in `quality-gates.toml`, and
`[tool.coverage.run] omit` in `pyproject.toml`. When #325 started delivering `scripts/mutation_*.py`, neither list
named them, and troupe's coverage gate failed (troupe-run/troupe#444, #333).

#271 asks for a limit on file size, so Claude's review, which reads every changed file whole, can read each in one or
two Reads. The probe for #268 (`review-covers-the-diff` design, "Probe results") found a Read stops at about 25,000
tokens: ~41 KB of short lines, ~22 KB of long ones; a file over 256 KB can't be read without `limit` at all.
Measurements of all three repositories on 2026-11-19 are in https://github.com/troupe-run/infrastructure/issues/271#issuecomment-7007381851.

## Goals / Non-Goals

**Goals:**

- The gates leave delivered files out by reading the list that says what's delivered; no repository keeps a pattern
  for them.
- A size gate, in the delivered script, with thresholds and exceptions declared once per repository.

**Non-Goals:**

- Mutation testing's own file selection: it runs on changed files and has its own config (#325); not changed here.
- Splitting today's large files. Each is declared in `[size.allow]`; splitting is follow-up work.
- Removing troupe's and website's hand-written patterns: their own pull requests, after delivery (D7).
- A line-count limit: lines don't predict a Read (troupe's 88-line `transcript.jsonl` fixture is 52 KB).

## Decisions

### D1. The gates read the delivered list themselves

`quality_gates.py` reads `.github/guard-delivery.json` at the repository root once per run, and each gate drops the
paths it names (the list file itself is never Python, so naming it changes nothing). The script stays standalone: it
doesn't import the guard, which a receiving repository runs as a separate file, so it has its own small reader.

Unlike the guard's reader, which protects itself by treating an unreadable list as naming only itself, the gates'
reader fails: a malformed list is a `GateError` (exit 2), naming the file and the problem (not JSON, not an object,
`files` missing or not a list of strings). Treating it as empty would measure delivered files and fail for the wrong
reason; treating it as "everything" would hide real code. A missing file means nothing is delivered, as in
infrastructure, the source.

Alternative considered: a `[delivered]` setting in each `quality-gates.toml`. Rejected: it's the hand-kept list the
issue removes.

### D2. Where each gate drops them

- **Coverage**: after `coveragepy_counts`/`vitest_counts` make paths relative to the root, delivered paths are
  removed before `coverage_result` maps files to packages, so they count in no package's totals and are never "in no
  package". The report's other paths are unchanged.
- **Complexity**: `measured_path` returns false for a delivered path, beside the `exclude` check.
- **Size**: the same (D4).

Paths compare exactly, after the report's paths are made relative with forward slashes (`_relative`), since the
list holds repository-relative POSIX paths.

### D3. The failing test first uses a real case

The first test is troupe's own: its delivered list as of troupe 4ffa922d (copied as a fixture), a coverage.py report
in which `scripts/mutation_run.py` (delivered) is uncovered and the rest of `scripts` is covered, and troupe's
`scripts` package with baseline 88.4. It fails on main (the package measures below its baseline) and passes once
delivered files are dropped.

### D4. The size gate

A fourth gate, `quality_gates.py size [--base REV]`, run by `scripts/check.py` beside complexity on every check, local
and CI. It reuses `resolve_base` and `changed_lines` for the files the work adds or changes (deleted files aren't
measured), and for each measured file compares its size in the working tree with its size at the base (`git cat-file
-s base:path`, absent for a new file).

- A file is **measured** unless it's delivered, matches `[size] exclude`, or is binary: contains a NUL byte or isn't
  valid UTF-8. Lock files and state are text, so they go in `exclude`.
- Its **limit** is its `[size.allow]` ceiling if it has one, else `block_above`.
- It **fails** when its size is above its limit and it's new, or larger than at the base. Like complexity, a file
  already over that is edited without growing passes.
- It **notes** a file above `warn_above` that doesn't fail.
- Every run checks `[size.allow]`: an entry whose file is missing, or whose size is at or under `block_above`, fails
  as stale, saying to remove it; an entry whose ceiling isn't above `block_above` fails as a config error.

Bytes, not characters or tokens: what git stores, cheap to read, and within a few percent of the Read cap's ratio for
the source here.

### D5. Thresholds (owner's decision, pending)

Proposed, with figures in that comment: `warn_above = 40960` (40 KiB, about one Read of code) and
`block_above = 65536` (64 KiB, two to three Reads). Alternatives: 48 KiB (adds 4 troupe and 3 infrastructure files to
the exception list) or 100 KiB (only 3 infrastructure files over; lets a file need four Reads). Each repository
declares its own values; the proposal is the same values in all three.

### D6. The exception list (owner's decision, pending)

Proposed: `[size.allow]`, a table of path to ceiling in bytes, each set to the file's size today plus 8 KiB headroom,
rounded up to 1 KiB. The ceiling lets the most-edited files (infrastructure's `docs/development-workflow.md` and the
development-workflow spec, touched by 81 commits in the last month, and touched by this change) take ordinary edits,
while still stopping unbounded growth, and the stale check makes the list shrink as files are split.

Alternatives: no headroom (a declared file can't grow at all; the next change that adds to it splits it), or fully
exempt entries with a split issue per file.

Infrastructure's list, if the proposal is taken: `scripts/guard.py`, `scripts/tests/test_claude_review_workflow.py`,
`.github/workflows/claude-review.yml`, `openspec/specs/development-workflow/spec.md`, `docs/development-workflow.md`.
Its `exclude`: `**/fixtures/**`, `openspec/changes/archive/**`,
`uv.lock`, `tofu/terraform.tfstate`.

### D7. Sequencing across repositories: `[size]` is optional in this change

The delivered script reads `quality-gates.toml` strictly, so today's copy in troupe and website refuses an unknown
`[size]` table: neither can declare it before the new script arrives. If the new script required `[size]`, the apply
that delivers it would turn troupe's and website's main red until each merged a pull request adding it.

So, as `[coverage]` is, `[size]` is optional in this change: a repository without it gets "size: not declared in this
repository" and its other gates run. Order:

1. This change merges, with `[size]` in infrastructure's own `quality-gates.toml`.
2. The owner approves the apply that delivers the new script to troupe and website.
3. troupe and website each add `[size]` (the owner's thresholds and their own exception list) and remove their
   hand-written delivered-file patterns (`[complexity] exclude`, troupe's `[tool.coverage.run] omit`), in one pull
   request each.
4. A follow-up infrastructure change makes `[size]` required once both have it, so a gate can't be switched off by
   leaving its table out. It's raised as an issue when this change merges, on the board.

Alternative considered: required from the start, with the delivery held until troupe and website are ready. Rejected:
they can't be ready, since their current script refuses the table.

## Risks / Trade-offs

- [A repository gets a file delivered that it also authors] → can't happen: the guard refuses edits to delivered
  files, and the list is generated from what's delivered.
- [The list and the delivered files disagree for one run] → the list and the files are delivered in one apply, from
  one commit (`guard_lists` is generated from `guard_target_files`).
- [Bytes overstate a Read for short-line files] → the warning sits at ~one Read of code; the probe's short-line case
  holds more per Read, so it errs towards warning early.
- [A stale `[size.allow]` entry fails a check that didn't touch the file] → only when the file shrank below the limit
  or was removed, which happens in the change that split it; the message names the entry to remove.
