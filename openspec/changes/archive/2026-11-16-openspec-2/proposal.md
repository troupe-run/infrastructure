# Proposal

## Why

OpenSpec 2.0.0 (released 2026-11-11) is now the version installed locally, but the guard check still installs 1.14.3
(`OPENSPEC_VERSION` in `.github/workflows/guard.yml`), and this repository's OpenSpec files were generated by 1.14.3
(#308). 2.0 moves the skills to `.agents/skills/` and removes the `/opsx:*` slash commands, which the guard's own
messages still tell people to type. troupe-run/troupe#423 and troupe-run/website#116 upgrade those repositories;
this change moves the org's pin and the guard with them.

## What Changes

- **Pin OpenSpec 2.0.0 in `guard.yml`.** `OPENSPEC_VERSION` moves from `1.14.3` to `2.0.0`. The delivery takes it to
  troupe and website.
- **Name the 2.0 skills in the guard's messages.** `scripts/guard.py` says `/opsx:propose` in the
  `commit-branch-change` and `edit-branch-change` fixes and in the session-start summary, and `/opsx:apply` in the
  summary. They become `/openspec-propose` and `/openspec-apply-change`, the names OpenSpec's upgrade guide maps them
  to. Its test of the `commit-branch-change` fix follows.
- **Re-capture `openspec-strict`'s fixtures with 2.0.0.** The guard reads `openspec validate --all --strict --json`.
  2.0.0's report for both fixtures is identical to 1.14.3's apart from `durationMs`, as are its exit status and error
  output, so the parsing doesn't change. The fixtures and the version their tests name move to 2.0.0, so they record
  what CI now runs.
- **Regenerate this repository's OpenSpec files with 2.0.0.** `openspec update`, committed exactly as written: six
  skills move to `.agents/skills/` with links from `.claude/skills/`, and the six `.claude/commands/opsx/` files are
  deleted. The dry run lists no locally edited file to keep.
- **Name the 2.0 skills in the docs.** `CLAUDE.md` (steps 2, 3 and 6) and `docs/standard-changes.md` (the labels
  procedure) say `/opsx:propose`, `/opsx:apply` and `/opsx:archive`.

Archived changes and the recorded tofu plan fixture (`scripts/tests/fixtures/plan-pr96.txt`) keep the names they were
written with.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

None. No requirement in `openspec/specs/` names a slash command or an OpenSpec version, so the change sets
`skip_specs: true`. The development-workflow doc's "Moving the OpenSpec version" procedure applies as written.

## Impact

- Changed: `.github/workflows/guard.yml`, `scripts/guard.py`, `scripts/tests/test_guard_commit_rules.py`,
  `scripts/tests/test_guard_openspec.py`, `scripts/tests/fixtures/openspec-strict/*/report.json`, `CLAUDE.md`,
  `docs/standard-changes.md`, `.agents/skills/` (added), `.claude/skills/openspec-*` (links), `.claude/commands/opsx/`
  (deleted).
- Delivery: `guard.yml` and `guard.py` reach troupe and website by the apply after this merges. This change merges
  only after troupe#423 and website#116 have merged, so neither repository gets the 2.0.0 pin or the new names while
  still on 1.14.3's layout. Before the plan's approval, 2.0.0's `openspec validate --all --strict` runs over each
  governed repository's `main`, and the pull request names any failure (docs/development-workflow.md, "Moving the
  OpenSpec version").
- Rollback: revert the merge and deliver again.
